# UI Audit — Desktop MVP

Date: 2026-09-02
Reviewer: DaVinci
Viewport: 1920×1032 native Chrome window
Build reviewed: local frontend at `http://127.0.0.1:5173`

## Result
The stage structure is implemented and visually consistent, but the current UI is still an engineering console rather than a production-ready content creation cockpit. Core stages are reachable; visual review and timeline tasks need major usability work before the desktop UI should be considered complete.

## What Works
- The stage rail clearly exposes Story, Storyboard, Generate, Review, Timeline, and Export.
- Dark visual language is consistent across pages.
- Primary actions use a consistent purple/green hierarchy.
- Story fields are grouped logically.
- Status color is visible in Storyboard and Review.
- Export formats are clearly enumerated.

## P0 — Blocks Core Workflow

### 0. Provider and execution state are misleading

The Generate screen can label a row `Local ComfyUI` while also showing a small `mock` badge, and it reports internal `Queued / Running / Completed` states even when no job has been submitted to ComfyUI. A page-level `Project not found` error does not identify the stale project or explain whether the queue is safe to clear.

Acceptance:
- Show an explicit page-level execution banner: `REAL · ComfyUI connected` or `SIMULATION · Mock provider`; never mix the two identities in one provider label.
- Disable real generation until an API-format workflow, required mappings, project, and provider health all pass preflight.
- A real submitted row must display `prompt_id` and distinguish `Submitting`, `Accepted by ComfyUI`, `Running on ComfyUI`, and `Output downloaded`.
- Internal/mock jobs use separate `Simulated` status language and cannot appear as evidence of real ComfyUI execution.
- `Project not found` identifies the missing project, pauses affected jobs, and offers `Switch project` / `Clear stale jobs`; it must not coexist with apparently successful project jobs without explanation.
- Provider, model/workflow, output type, estimated cost, and Local/Cloud privacy posture remain visible per shot.

### 1. Review media preview is broken or unavailable
Evidence: `exports/ui-audit/04-review.png`

The approved take card shows a generic broken/empty image area instead of the generated video or a poster frame. A reviewer cannot make an informed approval decision without seeing the take.

Acceptance:
- Video takes show a playable muted preview or reliable poster frame.
- Image takes show the real image with contain/cover behavior documented.
- Loading, unavailable, and corrupt-media states are visually distinct.
- Clicking a take opens useful inspector content immediately.

### 2. Storyboard is a data table, not a visual storyboard
Evidence: `exports/ui-audit/02-storyboard.png`

The current row exposes IDs and prompt text but no thumbnail, shot framing, duration block, take count, or continuity context. It cannot support visual sequencing.

Acceptance:
- Each shot has a thumbnail/poster frame.
- Cards show shot number, type, camera, subject, duration, status, and approved-take state.
- Scene grouping and ordering remain obvious with 9–15 shots.
- Users can switch between compact table and visual card/grid views.

### 3. Timeline is a list, not an editable timeline
Evidence: `exports/ui-audit/05-timeline.png`

The screen shows a single text row with in/out values. It does not communicate relative duration, sequence, transitions, or media content.

Acceptance:
- Clips render as proportional blocks on a horizontal time ruler.
- Every block has a thumbnail and duration.
- Selection opens timing and transition controls in the inspector.
- Empty, one-clip, and multi-scene states remain understandable.
- Retiming is visible before render.

## P1 — Major Usability Issues

### 4. Type and controls are too small
Evidence: all screenshots

Navigation labels, metadata, diagnostics, table rows, and secondary controls are difficult to read at a 1920-wide desktop viewport. The design appears scaled down rather than information-dense.

Acceptance:
- Body text is generally 13–14 px minimum.
- Metadata is 12 px minimum with adequate contrast.
- Primary controls are at least 32–36 px high.
- Navigation hit areas remain at least 44 px even when visually compact.

### 5. Inspector consumes width while empty
Evidence: all screenshots

The right inspector occupies roughly one fifth of the screen even when no item is selected, leaving a large dead region.

Acceptance:
- Inspector starts collapsed or uses a narrower empty state.
- Selecting a scene, shot, take, or clip opens the relevant inspector automatically.
- Inspector width is resizable or responsive.
- Pages that do not use inspector content, especially Export, can reclaim the space.

### 6. Generate page exposes raw diagnostics too prominently
Evidence: `exports/ui-audit/03-generate.png`

Workflow mapping diagnostics dominate the screen with repeated low-level node mappings. This is useful for setup/debugging but obscures the primary generation workflow.

Acceptance:
- Top summary shows readiness, blocking count, warnings, provider, and workflow.
- Technical node mappings live under an “Advanced diagnostics” disclosure.
- Repeated workflow issues can be grouped.
- Each blocker has one clear corrective action.

### 7. Review cards are too small for visual judgment
Evidence: `exports/ui-audit/04-review.png`

A narrow card surrounded by empty canvas wastes space and cannot support comparing alternate takes.

Acceptance:
- Default grid provides 3–4 useful cards per desktop row.
- Cards reserve a consistent 16:9 media area.
- Hover/focus actions do not cover important imagery.
- Compare mode can show at least two takes at meaningful size.

## P2 — Polish and Clarity

### 8. Excessive empty canvas without purposeful empty states
Storyboard, Review, and Timeline leave most of the center panel unused. Empty space should either support larger media or provide concise next-step guidance.

### 9. Status language and hierarchy need stronger consistency
Scene status, shot status, take status, and provider readiness should use the same semantic tokens and avoid tiny pills that are hard to scan.

### 10. Export page should not show an empty inspector
Evidence: `exports/ui-audit/06-export.png`

The export list itself is clear, but the unused inspector creates unnecessary imbalance. A delivery summary or recent exports panel would be more useful.

## Responsive Audit Still Required
A mobile/tablet audit is not complete. Required viewports:
- 1440×900 desktop
- 1024×768 tablet landscape
- 768×1024 tablet portrait
- 390×844 phone

At each viewport verify:
- Stage navigation remains reachable.
- Inspector becomes a drawer/sheet rather than squeezing content.
- Story forms do not create horizontal scroll.
- Storyboard cards and media previews remain readable.
- Primary actions remain visible and tap targets meet minimum size.
